# Веб-версия «Снабжение»

Веб-приложение работает поверх существующей Python-логики. Настольная версия
продолжает запускаться через `start.bat`.

## Что перенесено

- Вход и выход, создание аккаунтов администратором, опциональная регистрация.
- Отдельная база SQLite и папка файлов для каждого аккаунта.
- Поставщики: создание, изменение, удаление, категории и исключение из рассылок.
- Поиск через централизованный Codex, источники контактов, одобрение/отклонение
  найденных компаний и выгрузка Excel.
- Создание черновиков с заявкой XLSX и вложениями; отдельное действие отправки.
- Получатели, добавление компаний в рассылку, статусы ответа и завершение ожидания.
- Входящие, ручная привязка к получателю, прочитанные/непрочитанные письма.
- Просмотр переписки и файлов, ответ с цитатой и вложениями.
- Сводная Excel, резервная копия, журнал и очередь фоновых операций.
- Проверка почты по расписанию при активных рассылках, независимо от браузера.
- Импорт папки данных настольной версии в новый аккаунт.

## Локальный запуск на Windows

Из корня репозитория, Python 3.11+:

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements-web.txt
.\.venv\Scripts\python -m webapp create-user --email buyer@example.com
.\.venv\Scripts\python -m webapp serve --port 8787
```

Команда создания пользователя интерактивно запрашивает пароль (от 12 символов).
Откройте [локальную версию](http://127.0.0.1:8787) и войдите созданным аккаунтом.
По умолчанию данные лежат в `.dev-data/web`, регистрация закрыта. Другие
пользователи создаются той же командой `create-user`. Для смены забытого пароля:

```powershell
.\.venv\Scripts\python -m webapp reset-password --email buyer@example.com
```

Смена пароля отзывает все сессии аккаунта. Пароль почты вводится отдельно на
странице «Настройки», хранится в зашифрованном виде и не возвращается браузеру.

Путь можно задать переменной `WEB_DATA_DIR`. Всегда используйте одну и ту же
папку при создании пользователей, запуске и восстановлении сервера.

## Сервер и Codex через Docker Compose

### Поиск через OpenAI API (экономный режим)

При запуске `python -m webapp ...` приложение читает `.env` из корня проекта.
Укажите `OPENAI_API_KEY`; прежнее имя `chatgpt_api` также поддерживается.
Ключ остаётся на сервере и не выдаётся браузеру. Авторизация Codex не требуется.

```dotenv
SEARCH_PROVIDER=openai
OPENAI_SEARCH_MODEL=gpt-6-luna
OPENAI_SEARCH_BUDGET_USD=5
```

Используется Responses API с `web_search`: один запрос без автоматических повторов,
до 5 компаний, не более 2 обращений к инструменту и до 4000 выходных токенов.
Сохраняются только компании со ссылками, присутствующими в источниках API.
Это подтверждает происхождение ссылок, но не заменяет ручную проверку компании.

`OPENAI_SEARCH_BUDGET_USD` — общий накопительный лимит этой установки для всех
аккаунтов; записи хранятся в `server.db/search_spend`. Перед запросом резервируется
$0.25. При получении статистики токенов резерв заменяется консервативной оценкой
стоимости с округлением вверх до цента. При таймауте или отсутствии статистики
резерв сохраняется: повтор может быть оплачен отдельно. Оценка использует тарифы
Standard GPT-6 Luna и web search на 11.11.2026; при изменении тарифов расчёт нужно
обновить. Это не запрос баланса OpenAI и не ограничение других приложений,
использующих тот же API-проект. Фактические расходы проверяются в OpenAI Usage.
[Тарифы](https://developers.openai.com/api/docs/pricing).

Для OpenAI достаточно `docker compose up -d --build web`; сервис `search` и
`CODEX_GATEWAY_TOKEN` не нужны. Секрет из `.env` передаётся в окружение web,
а не включается в образ. Запрос к модели для проверки доступа не расходует
генеративные токены; полноценный поиск оплачивается.

### Прежний вариант с Codex CLI

Для этого варианта установите `SEARCH_PROVIDER=codex` и запускайте
`docker compose --profile codex up -d --build`.

Для многопользовательского размещения предусмотрены два сервиса:

```text
Браузер → HTTPS-прокси → web (Flask + Waitress + очередь)
                         ├─ app-data: аккаунты, базы, пароли, файлы
                         └─ HTTP → search (Codex CLI, один поиск за раз)
                                    └─ codex-auth: серверная авторизация Codex
```

Контейнер `search` не монтирует `app-data`, не имеет доступа к почтовым паролям
и базам пользователей. Получает только запрос, регион, число компаний и категории.
Его HTTP-порт не публикуется наружу. `CODEX_GATEWAY_TOKEN` нужен обоим сервисам.

1. Скопируйте `.env.example` в `.env`, замените `CODEX_GATEWAY_TOKEN` случайной
   строкой (команда генерации приведена в файле). Не коммитьте `.env`.
2. Соберите и запустите сервисы:

```sh
docker compose --profile codex up -d --build
docker compose exec web python -m webapp create-user --email buyer@example.com
```

3. Настройте авторизацию Codex один раз внутри отдельного контейнера. Для
   поддерживаемого вашим аккаунтом входа через устройство:

```sh
docker compose exec search codex login --device-auth
docker compose exec search codex login status
```

Следуйте инструкциям Codex. Возможность входа зависит от настроек аккаунта и
рабочего пространства. Авторизация через API тоже поддерживается Codex; её
нужно настроить отдельно с учётом биллинга. Поддержка headless-входа сама по себе
не определяет лимиты и доступные модели конкретного аккаунта.
[Официальная документация авторизации](https://learn.chatgpt.com/docs/auth).

4. Войдите в веб-приложение, подключите почту и запустите пробный поиск.

На одной папке веб-данных должен работать **один процесс web**: его восемь
HTTP-потоков обслуживают пользователей, а внутренние потоки исполняют очередь.
Запускайте именно `python -m webapp serve`, чтобы работали очередь и расписание.
Не запускайте через `flask run`, несколько Gunicorn workers или несколько реплик.
При перезапуске незавершённые операции помечаются ошибкой и не отправляются повторно
автоматически. Проверьте «Отправленные» в почте перед ручным повтором отправки.

## HTTPS и домен

Compose по умолчанию публикует web только на `127.0.0.1:8080`. Перед внешним
использованием разместите перед ним HTTPS-прокси, задайте в `.env`:

```dotenv
WEB_TRUSTED_HOSTS=procurement.example.com
WEB_SECURE_COOKIES=1
WEB_ALLOW_REGISTRATION=0
```

Пример фрагмента для уже настроенного HTTPS-сервера Nginx на том же хосте:

```nginx
client_max_body_size 25m;
location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $remote_addr;
}
```

Если прокси передаёт исходный IP посетителя, установите `WEB_TRUSTED_PROXY` в
**точный адрес непосредственного прокси, видимый контейнером web**. При запуске
без Docker с Nginx на том же хосте это обычно `127.0.0.1`. В Docker это может
быть адрес шлюза сети. Без настройки доверия лимит IP применяется к адресу
прокси; заголовки от неизвестных источников не используются. Не задавайте `*`.
[Параметры Waitress](https://docs.pylonsproject.org/projects/waitress/en/stable/arguments.html).

На сервере должны быть разрешены исходящие подключения к выбранному SMTP/IMAP
сервису и к Codex. Поиск и почта используют отдельные очереди: долгий поиск
не останавливает отправку и проверку писем.

Публичную регистрацию можно включить через `WEB_ALLOW_REGISTRATION=1`, если
нужен свободный доступ. Для внутреннего сервиса оставьте создание пользователей
администратору. В первой версии нет проверки email, самостоятельного сброса
пароля по почте и панели администрирования пользователей.

## Перенос существующих данных

Остановите настольное приложение и веб-сервер. Создайте новый веб-аккаунт и
выполните импорт **до его первого входа**:

```powershell
python -m webapp import-desktop --email buyer@example.com --source "$env:LOCALAPPDATA\AutomationSystem"
```

Если старая программа использует `RosaMailCollector` или другой путь, укажите
фактическую папку с `app.db`, `campaigns` и `unmatched`. Команда копирует данные,
исходники не меняет; пути внутри базы переписываются на папку аккаунта. Внешние
пути вне папки данных отклоняются. Существующие веб-данные не перезаписываются.
В Docker передайте исходную папку в одноразовый контейнер только для чтения и
выполните ту же команду с путём монтирования.

Пароль из Windows Credential Manager не переносится. После импорта укажите
адрес и пароль почты в веб-настройках.

## Хранение и восстановление

Сохраняйте резервную копию **всей** папки `WEB_DATA_DIR` или Docker volume
`app-data` при остановленном сервере. В ней находятся `server.db`, `secret.key`
и `accounts/`. Без `secret.key` нельзя расшифровать пароли почты. Резервная копия
из интерфейса содержит бизнес-данные одного аккаунта, но не серверные аккаунты,
сессии и пароли почты. Авторизация Codex хранится отдельно в `codex-auth`.

Логи ошибок: `WEB_DATA_DIR/logs/server.log`; ошибки самого Codex —
`docker compose logs search`. Сообщения ошибок фоновых задач в браузере
не содержат внутренних путей и технических секретов.

## Сканы и проверка

### Демо-данные для интерфейса

В существующий тестовый аккаунт можно добавить поставщиков, 7 рассылок,
многошаговую переписку (включая Google Workspace), непривязанные письма,
тестовые счета XLSX и готовые демонстрационные сводные:

```powershell
$env:WEB_DATA_DIR = 'C:\projects\reply-tracker\.dev-data\web-preview'
python -m webapp seed-demo --email demo@example.test
```

Команда работает локально, без SMTP/IMAP и AI API. Использует вымышленные
компании и зарезервированные адреса `.test`, не меняет прежние записи и
не дублирует набор при повторном запуске. До добавления сохраняется резервная
копия базы. Данные и суммы в документах тестовые, не предназначены для оплаты.

### OCR и тесты

В Windows остаётся прежний Windows OCR. На Linux используется Tesseract с
языками `rus+eng` (установлены в Dockerfile). Сохраняются прежние ограничения
разбора форматов счетов: неожиданные документы требуют ручной проверки.

```sh
python -m unittest discover -s tests
```

Тесты проверяют два независимых аккаунта, файлы, очередь, сессии, CSRF,
шифрование паролей, импорт и интеграцию с сервером поиска через подменённые
ответы. Реальные SMTP/IMAP, Codex и распознавание ваших PDF требуют отдельных
проверок на выбранном сервере. Тесты сводной пропускаются без исходных документов.
