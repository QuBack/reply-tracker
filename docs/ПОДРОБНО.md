# Система автоматизации — подробное руководство

Локальное Windows-приложение для рассылки запросов поставщикам через Mail.ru,
контроля ответов и сохранения полученных PDF/Excel-файлов.

## Что уже работает

- справочник поставщиков;
- категории поставщиков и фильтр по категории;
- поиск новых поставщиков через Codex CLI с проверкой источников, списком
  кандидатов и выгрузкой в XLSX;
- создание рассылки и отдельное письмо каждому адресату;
- SMTP-отправка через Mail.ru;
- ручная проверка входящих;
- автоматическая проверка по таймеру и при следующем запуске;
- привязка ответов по цепочке письма, коду рассылки или отправителю;
- ручная привязка спорного письма;
- сохранение оригинального `.eml` и всех именованных вложений;
- статусы «ответ без файлов», «файлы получены», «отказ» и другие;
- отдельный статус «Исход отправки неизвестен» при обрыве соединения: такой
  адресат не отправляется повторно автоматически;
- обнаружение одинаковых файлов по SHA-256;
- создание XLSX-сводной по заявке и полученным счетам с ценой за тонну,
  рассчитанной по общей стоимости и массе партий;
- SQLite-база, журнал событий и ZIP-резервные копии.

## Запуск

Требуется Windows и Python 3.11 или новее. Для сводной установите библиотеки:

```powershell
python -m pip install -r requirements.txt
```

Почтовые функции запускаются и без этих библиотек. Создание сводной в этом
случае сообщит, что их нужно установить.

```powershell
python main.py
```

Или запустите `start.bat` двойным щелчком: он сам установит недостающее.

Главный экран — «Рассылки». Кнопка «Новая рассылка» открывает форму письма:
выберите поставщиков и исходную заявку XLSX. Заявка прикрепляется к письмам и
сохраняется для будущей сводной. Дополнительные вложения выбираются отдельно.
По выбранной рассылке справа видны поставщики и их ответы; двойной щелчок по
ответу открывает текст и файлы. Вкладка «Требуют внимания» показывает письма,
которые нужно привязать вручную; флажок «Все ответы» открывает полный список.
Журнал операций находится в «Настройках».

## Поиск поставщиков без API-ключа

Для поиска установите Codex CLI на этом компьютере и войдите в него через свой
аккаунт ChatGPT с доступом к Codex. Проверить вход можно командой
`codex login status`. Отдельный API-ключ приложению не нужен. Каждый человек,
который запускает поиск на своём компьютере, входит в Codex под своим аккаунтом;
использование ограничено возможностями и лимитами его плана.

На вкладке «Поиск поставщиков» опишите товар, требования и регион, затем нажмите
«Найти». Приложение запускает Codex CLI с веб-поиском и навыком
`.agents/skills/supplier-discovery/SKILL.md`. Во время поиска окно остаётся
доступным; поиск можно остановить. Найденные компании сохраняются в таблицу
кандидатов с категориями, ссылками на источники и статусом проверки.

Проверьте каждую карточку: откройте источник, исправьте данные и сохраните.
Codex принимает email и телефоны только со ссылкой на страницу, где они
опубликованы. Если сайт закрыт от бота и контактов нет, откройте сайт сами и
впишите email, телефоны, контактное лицо и адрес в карточку — страница с
контактами в этом случае необязательна. Кнопка «В справочник» добавляет
кандидата, у которого есть email или телефон. Поставщик без email хранится в
справочнике, но в рассылки не попадает (в столбце «Рассылки» — «Нет email»).
Поиск сам не отправляет писем. Вкладка «Поставщики» позволяет менять категории вручную и
фильтровать справочник. Кнопка «Выгрузить Excel» сохраняет список кандидатов
отдельно от сводной по счетам.

Источник подтверждает только то, что Codex нашёл страницу. Перед закупкой или
рассылкой проверьте, что сайт, ассортимент и контакт актуальны. Если Codex CLI
не установлен или вход не выполнен, поиск покажет ошибку; остальные почтовые
функции продолжают работать без него.

## Настройка Mail.ru

1. В Mail.ru откройте **Настройки → Все настройки → Безопасность → Пароли для
   внешних приложений**.
2. Создайте отдельный пароль с полным доступом к Почте.
3. В приложении откройте вкладку **Настройки**.
4. Укажите полный email и созданный пароль.
5. Нажмите **Сохранить и проверить**.

Основной пароль аккаунта использовать не нужно. Пароль приложения сохраняется
в Windows Credential Manager и не записывается в SQLite.

Используемые серверы:

- `imap.mail.ru:993`, SSL/TLS;
- `smtp.mail.ru:465`, SSL/TLS.

## Где хранятся данные

По умолчанию:

```text
%LOCALAPPDATA%\AutomationSystem
```

Там находятся база `app.db`, оригиналы писем, вложения, журнал и резервные
копии. Папку можно открыть со вкладки **Настройки**.

Для разработки или переносной установки путь можно переопределить:

```powershell
$env:AUTOMATION_DATA_DIR = "D:\AutomationData"
python main.py
```

## Как определяется ответ

Тема каждого письма получает код наподобие `[RFQ-2026-0001]`. Это служебный
номер рассылки, видимый адресату; он помогает распознать ответ, если почтовые
заголовки цепочки не сохранились. Это не ярлык Mail.ru.

Привязка выполняется в следующем порядке:

1. стандартные заголовки ответа `In-Reply-To` / `References`;
2. код рассылки в теме;
3. email отправителя, если у него только одна активная рассылка;
4. ручной выбор в интерфейсе.

Допустимыми документами ответа считаются `.pdf`, `.xls` и `.xlsx`. Получение
хотя бы одного такого файла переводит поставщика в статус «Файлы получены».
Все остальные именованные вложения тоже сохраняются, но не завершают ожидание.
В списке ответов результат указан для каждого отдельного письма. Общий статус
поставщика находится во вкладке «Рассылки»: если файл уже был получен,
более поздний ответ без файла не отменяет этот статус.

Если у адресата указан статус «Исход отправки неизвестен», проверьте доступные
сведения в Mail.ru и при необходимости уточните у адресата. Отсутствие копии в
«Отправленных» само по себе не доказывает, что письмо не ушло: приложение пока
не сохраняет её туда отдельно. Программа не повторяет такое письмо автоматически.

## Создание сводной

Во вкладке «Рассылки» выберите рассылку со статусом «Готово к сводной» и нажмите
«Создать сводную». Программа использует заявку XLSX, выбранную при создании
рассылки, возьмёт привязанные к ней счета, создаст файл в папке рассылки
`summary` и откроет его. Для старых рассылок с единственным исходящим XLSX
заявка определяется автоматически; если определить её нельзя, программа
попросит выбрать файл один раз и сохранит копию для повторных сводных.
Каждая строка заявки сохраняется отдельно. Для нескольких партий одной позиции
у одного поставщика цена за тонну считается как сумма стоимостей с НДС,
делённая на сумму масс в тоннах.

На листе «Партии» сохраняются номера счетов, файлы, строки, цены и масса. На
листе «Проверка» перечислены позиции с другой маркой, неизвестной длиной,
ошибками OCR и другими спорными данными. Их нужно проверить по исходным счетам
до закупки. Скан распознаётся локальной функцией Windows OCR; для него требуется
установленный русский язык распознавания Windows. Если распознавание не удалось,
файл явно отмечается в листе «Проверка».

Текущая версия разбирает счета PDF, подобные полученным примерам. Счета XLS/XLSX
сохраняются во входящих, но их позиции пока не извлекаются автоматически и
отмечаются для ручной проверки. Новые макеты PDF также могут потребовать
добавления правила извлечения.

Генератор можно запустить отдельно от почтового приложения:

```powershell
python generate_summary.py --request "заявка.xlsx" --offer "Поставщик=счёт.pdf" --output "сводная.xlsx"
```

Для нескольких счетов повторите `--offer`. Указывайте одного и того же
поставщика одним названием, чтобы его партии объединялись.

## Проверка тестов

```powershell
python -m unittest discover -s tests -v
```

Автоматические тесты используют временные данные и имитацию почтового сервера.
Они не отправляют реальные письма. Перечень обязательных сценариев приведён в
`TEST_PLAN.md`.
